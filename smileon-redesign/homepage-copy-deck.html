Feasibility check

Yes, this page can be built in Elementor and be fast, mobile-friendly and crawlable

The draft already uses native Elementor widgets (Heading, Text Editor, Button, Icon List, Image, Counter, Icon Box, Image Box, Toggle) inside flexbox containers, with separate mobile padding. That is the lightest way to build in Elementor, and anyone who uses Elementor can edit it. The main work is speed, not design: the live homepage is slow on mobile because of page weight and plugins, not because of Elementor itself.

For the person building it

Build, speed and launch checklist

Publish without losing rankings

  1. Paste the copy into draft 6836, preview it on mobile, then get it approved.
  2. Back up first, using Hostinger's one-click backup.
  3. Go to Settings → Reading → Homepage and choose page 6836. WordPress then serves it at / and redirects its own slug to the homepage.
  4. Redirect the old "Home" page (ID 4103, slug home-copy) to / with a 301, or set it to draft.
  5. Set the SEO title and meta from this deck, and update the FAQ schema to the questions above.
  6. In Elementor → Tools, click Regenerate CSS & Data, then purge the LiteSpeed cache.

Mobile speed (target LCP under 2.5s)

  • Elementor → Settings → Features: turn on Optimized Markup, Improved CSS Loading, Inline Font Icons and Lazy Load Background Images, and use Element Caching.
  • Hero: no entrance animation, and don't lazy-load the first doctor photo. Serve the collage as WebP at about 400 px wide on mobile.
  • Fonts: Elementor → Settings → Advanced → Load Google Fonts Locally. Use only Poppins 600/700 and Rubik 400/500.
  • Add-ons: in ElementsKit, Exclusive Addons, Royal Addons and Premium Addons, switch off every widget the site doesn't use. Their CSS and JS load on every page.
  • LiteSpeed Cache (Hostinger): page cache on, CSS/JS minify, delay JS, and Generate UCSS/CCSS. Test after each change.
  • Map as a static image, and the reviews widget lazy-loaded.
  • Don't paste large SVG illustrations. They are 40% of the current homepage's weight.

SEO and crawlability

  • Only one H1, which is the hero heading. All section titles are H2 and box titles are H3. Choose the tag in Content and the size in Style.
  • Every treatment and doctor box links to its page, which gives 15+ internal links from the homepage.
  • All images have descriptive alt text. Decorative icons don't need it.
  • Hostinger security: make sure the bot protection doesn't block Googlebot, Bingbot or the AI crawlers you want (GPTBot, PerplexityBot, ClaudeBot).
  • Keep the Dentist schema in step with the fact sheet: hours, phone and rating.

After publishing, check for errors

  • PageSpeed Insights (mobile and desktop). Goal: performance 80+, LCP under 2.5s, CLS under 0.1.
  • Google Rich Results Test: Dentist and FAQ show with no errors.
  • Search Console → URL Inspection → Test live URL, then Request indexing.
  • Tap every button on a real phone: Book, Call, WhatsApp, Directions.
  • Check that the 301 from the old Home page works, and that there are no 404s in Search Console after a week.
